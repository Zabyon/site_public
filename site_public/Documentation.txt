La partie Documentation Fonctionnelle/Business doit se dérouler selon cet enchaînement :

1. Objectifs et Périmètre
  Finalité : Le site a pour but :
     de présenter l'association
     de renseigner sur les événements de l'asso
     de donner un point de contact
     de centraliser la gestion des Jeux pour les membres
     de permettre la réservation d'un ou plusieurs Jeu
     de permettre la réservation d'une Table les soirs d'asso

  Périmètre (Scope) : 
    Inclus :
      Authentification simple par mail+MDP
      Gestion des session on line (pas de cookie pour le moment)
      Gestion des "pseudo"
      Création et Suppression en toute autonomie
    Exclu :
      Gestion des annuités/paiement...
      Gestion de compte-rendu d'asso

Terminologie :  
    userName : adresse email d'un compte
    Emprunt  : Fiche permettant de suivre ce qui est pris ou non
    token    : Jeton d'authent permettant de s'authentifier auprès de l'API
    visiteur  : Externe a l'association souhaitant se renseigner sur celle ci
    adhèrent : membre ayant la possibilite de se creer un utilisateur pour voir les pages privé
    utilisant : adherent ayant cree son compte sur le site

2. Identification des Acteurs (Le "Qui")
Rôles Acteurs : 
    Visiteur     : "Pas implémenté" pour le moment (site visible sans authent --> Vitrine asso)
    Adhérents : Personne ayant cotisé à l'association.
    Utilisateur  : Personne pouvant s'authentifier et avoir accès à la liste de Jeu et peut réserver/Emprunter
    Admin        : Niveau le plus haut de droits (à segementer peut êttre après)

Besoins par Rôle : 
    Visiteur     : Accès https au site (rien de particulier juste accès à du html)
    Adhérents : Doit pouvoir sur le mail fourni a l'adhésion de creer un compte utilisateur.
    Utilisateur  : Une fois authentifié doit pouvoir, gérer son "pseudo", supprimer son compte, créer/modifier/supprimer un Emprunt/Réservation
    Admin        : Droit de vie ou de mort sur le code/infra

    En tant que Visiteur, je veux pouvoir consulter :

    En tant qu'Utilisateur, je veux pouvoir :
      M'enregistrer (OK) afin d'avoir accès au site
      M'authentifier (OK) afin d'accéder aux données de l'asso et celle de mon compte

4. Modélisation des Données (Le MCD MERISE)
      Entités :

6. Outils utilisés et raison
Dans un contexte ou la plupart des associations s'asseoit sur les donnees de leur utilisateurs / adhérents
Azurealpes s'engage a utiliser des que possible des outils libres ne recueillant pas d'informations qui ne seraient pas nécessaire auprès des utilisateurs.

Pour cela, nous utiliserons :
Framaforms (pour remplacer Google Forms)
Proton CAlendar/ Framagenda (Google Agenda)
FramaPDF (Adobe Acrobat)
OpenStreetMap (Google Maps)
